# 공부메이트

> 계획부터 복습까지, 매일 공부를 함께 챙겨 주는 스터디 플래너

- 배포 주소: https://yongshimsaeyeon.github.io/uiuxprogramming/
- 저장소: https://github.com/YONGSHIMSAEYEON/uiuxprogramming

## 프로젝트 소개

| 항목 | 내용 |
| --- | --- |
| 서비스 | 공부메이트 — 과목과 목표를 등록하면 하루 공부 계획을 나눠 주는 스터디 플래너 |
| 주요 사용자 | 공부 계획을 세워도 며칠 만에 흐지부지되는 대학생 |
| 서비스 목적 | 해야 할 공부를 작게 나누고, 매일 얼마나 해냈는지 한눈에 보여 줘서 공부 습관을 끝까지 이어 가게 한다 |
| 핵심 행동 | **첫 공부 계획 만들기** — 과목을 적고, 이번 주 목표와 하루 공부 시간을 골라 계획을 확정한다 |
| 완료 조건 | 확정 팝업에서 '계획 확정'을 눌러 **"공부 계획이 만들어졌어요"** 완료 화면에 도착하고, 다음에 할 행동(오늘의 할 일 체크)을 안내받는다 |
| 새 행동 (중간고사) | **내 공부 계획 목록** — 완성한 계획을 목록에 저장하고, 목표로 찾아 다시 열어 보거나, 다 끝난 계획을 지운다 |

## 중간고사에서 새로 추가한 것

7주차 흐름의 **끝(4단계 완료 화면)** 에 '내 계획 목록에 저장' 버튼을 붙여, 완성한 계획이 **내 공부 계획** 목록에 쌓이게 했습니다. 목록에서는 목표로 찾기(결과가 없으면 다른 선택 안내), 자세히 보기, 삭제(확인 팝업에서 취소 가능)를 할 수 있습니다.

**왜 이 기능인가:** 사용자는 계획을 세워도 며칠 만에 잊어버리는 대학생입니다. 7주차까지는 계획을 만들면 완료 문구만 보고 끝났기 때문에, 다음에 다시 볼 곳이 없었습니다. 만든 계획을 모아 두고 다시 열어 보게 해야 "계획을 끝까지 지킨다"는 서비스 목적에 이어집니다. 과목이 여러 개가 되면 목표(시험 대비 · 과제 제출 · 매일 복습)별로 찾을 수 있어야 하고, 끝난 계획은 지워야 목록이 깔끔하게 유지됩니다.

### 연결 지점

```
7주차: [첫 공부 계획 만들기] → 1 과목 → 2 목표·시간 → 3 확인 → (확정 팝업) → 4 완료
                                                                                │
8주차:                                                         [내 계획 목록에 저장]
                                                                                ▼
                        내 공부 계획 목록 ── [목표로 찾기] ── 결과 없음 → [전체 보기] / [새 계획 만들기]
                                          ├─ [자세히 보기] ↔ [접기]
                                          └─ [삭제] → 확인 팝업 → [취소] / [삭제]
```

- 새 화면을 만들지 않고 이용 방법(`#steps`) 안, 계획 만들기 흐름 바로 아래에 `#planList`를 붙였습니다. 메뉴에도 '내 공부 계획' 링크를 추가했습니다.
- 목록은 브라우저 저장소(`localStorage`)에 보관해서 새로고침해도 남습니다.
- 담당: `index.html` = 저장 버튼 · 목록 영역 · 삭제 팝업 구조 / `style.css` = 목표별 이름표 색, 저장 실패(`is-error`) · 방금 저장(`is-new`) · 지난 시험일(`is-past`) 상태, 모바일 배치 / `script.js` = 저장 조건 검사, 목록 다시 그리기, 찾기 · 자세히 보기 · 삭제 이벤트

### 새 기능의 행동 → 조건 → 반응 → 다음 행동

| # | 사용자 행동 | 확인할 조건 | 성공 반응 | 다른 분기 반응 | 다음 행동 |
| --- | --- | --- | --- | --- | --- |
| 1 | 완료 화면에서 '내 계획 목록에 저장' | 목록이 5개로 가득 찼는가? 같은 과목이 이미 있는가? (대소문자 무시) | 초록 문구 "'데이터베이스' 계획을 저장했어요…", 버튼 "저장 완료"(비활성), 목록에 초록 테두리 카드 추가 | **오류**: 가득 참 → "목록은 최대 5개까지예요. … 다 끝난 계획을 지운 뒤 다시 저장해 주세요." / 중복 → "'데이터베이스' 계획이 이미 목록에 있어요. 목록에서 예전 계획을 지운 뒤 저장하거나, '다시 만들기'로 다른 과목을 만들어 주세요." (빨간 문구, 완료 화면·값 유지) | 목록에서 계획 확인 / 오류면 목록에서 지우고 다시 저장하거나 다시 만들기 |
| 2 | '목표로 찾기'에서 목표를 고른다 (change) | 고른 목표의 계획이 있는가? | 그 목표 카드만 표시, "과제 제출 계획 1개 / 전체 5개" | **결과 없음**: "'과제 제출' 목표로 저장한 계획이 없어요. 전체 계획을 보거나 새 계획을 만들어 보세요." + [전체 보기] [새 계획 만들기] / 저장한 계획이 아예 없으면 [첫 공부 계획 만들기]만 표시 | 전체 보기 → 모든 카드 / 새 계획 만들기 → 흐름 1단계(초기화)로 이동 |
| 3 | 카드의 '자세히 보기' | 시험 대비인가? 시험일이 지났는가? | 목표 · 하루 공부 시간 · 저장한 날 표시, 시험 대비면 "D-52"처럼 남은 날, 버튼이 '접기'로 | 시험일이 오늘이면 "오늘이 시험날이에요!", 지났으면 빨간 글자 "이미 지났어요. 다 끝난 계획이면 지워 주세요." | 접기 / 삭제 |
| 4 | 카드의 '삭제' | — | 확인 팝업에 지울 계획 요약 표시 | — | 취소 / 삭제 |
| 5 | 팝업에서 '취소' | — | — | **취소**: 팝업만 닫히고 목록 그대로 | 계속 목록 사용 |
| 6 | 팝업에서 '삭제' | 지운 계획이 지금 완료 화면의 계획인가? 남은 결과가 있는가? | 카드가 사라지고 "'자료구조' 계획을 지웠어요. 저장한 계획 4개" | 완료 화면의 계획을 지웠다면 저장 버튼이 다시 켜지고 "다시 저장할 수 있어요" 안내 / 지운 뒤 결과가 0개면 결과 없음 안내 | 다시 저장 / 전체 보기 / 새 계획 만들기 |

### 다시 시작 · 값 유지 규칙

- **다시 만들기**(7주차 버튼): 계획 입력값과 함께 저장 버튼 · 저장 안내 문구도 처음 상태로 돌아갑니다. 이미 저장한 목록은 지우지 않습니다.
- **새 계획 만들기**(목록의 결과 없음 버튼): 다시 만들기와 같이 초기화한 뒤 흐름 1단계로 화면을 옮기고 과목 칸에 커서를 둡니다.
- 저장에 실패해도 완료 화면과 입력값은 그대로 남아, 목록에서 지운 뒤 바로 다시 저장할 수 있습니다.
- 저장하면 '목표로 찾기'가 '전체 보기'로 돌아가, 다른 목표로 찾던 중이라도 방금 저장한 계획이 보입니다.

## 파일 구조

```
uiuxprogramming/
├── index.html          구조 (header · nav · main 안의 section들 · footer)
├── script.js           행동 (신청 폼 · 탭 · 이벤트 · 계획 만들기 흐름 · 계획 목록)
├── README.md
└── assets/
    ├── css/style.css   표현 (색 변수 · 반응형 · 상태 class)
    └── images/service.jpg
```

| 영역 | 내용 |
| --- | --- |
| `#about` 서비스 소개 | 소개 문구와 앱 화면 이미지 |
| `#features` 주요 기능 | 오늘의 할 일 · 진도 그래프 · 공부 알림 카드 3개 |
| `#planner` 미리 써 보기 | 탭 3개로 기능 체험 (체크박스 · 공부 시간 막대 · 알림 설정) |
| `#steps` 이용 방법 | 이용 3단계 + **첫 공부 계획 만들기 흐름 (7주차)** + **내 공부 계획 목록 `#planList` (중간고사)** |
| `#subscribe` 무료로 시작하기 | 이메일 신청 폼 (입력 중 형식 안내, 신청 완료 후 버튼 비활성) |

## 사용자 흐름

이용 방법의 첫 단계("과목과 이번 주 목표를 등록합니다")를 실제로 해 보는 흐름입니다. 단계는 4개입니다.

```
[첫 공부 계획 만들기] → 1. 과목 입력 → 2. 목표·시간 선택 → 3. 입력 내용 확인 → (확정 팝업) → 4. 완료
                          ↑               ↑                     │
                          └──── 이전 ─────┴──────── 이전 ────────┘
                                                    완료 → [다시 만들기] → 1단계 (모두 초기화)
```

| 단계 | 화면 | 필수 값 | 다음 행동 버튼 |
| --- | --- | --- | --- |
| 시작 | 이용 방법 아래 `#planStart` | — | 첫 공부 계획 만들기 |
| 1 | 과목 이름 입력 | 과목 이름 (공백만 입력도 빈 값으로 처리) | 공부 목표 고르기 |
| 2 | 공부 목표 · 하루 공부 시간 선택 | 공부 목표 / **시험 대비일 때만** 시험 날짜(오늘 이후) | 이전 · 입력 내용 확인 |
| 3 | 입력한 과목 · 목표 · 시간 확인 | — | 이전 · 계획 만들기 → 확정 팝업 |
| 4 | 완료 문구 + 다음에 할 일 안내 | — | 다시 만들기 |

화면 위쪽의 진행 표시(`#planProgress`, `aria-live`)가 `1 / 3 · 계획 만들기 단계` → `2 / 3` → `3 / 3` → `계획 완성`(초록)으로 바뀝니다.

### 상태 정리

| 상태 | 화면 |
| --- | --- |
| 입력 전 | 흐름 영역 숨김, 시작 버튼 "첫 공부 계획 만들기" |
| 입력 중 | 현재 단계 하나만 표시, 진행 표시 `n / 3` |
| 오류 | 고칠 칸에 빨간 테두리(`has-error`, `aria-invalid`) + 칸 아래 수정 방법 문구, 해당 칸으로 커서 이동, 현재 단계에 머무름 |
| 선택 | 시험 대비를 고르면 시험 날짜 칸이 나타나고, 다른 목표로 바꾸면 날짜 칸이 숨겨지며 값도 지워짐 |
| 확인 | 3단계에 입력·선택 값 표시 |
| 확정 팝업 | `<dialog>`로 요약 표시. **다시 확인**=팝업만 닫고 값 유지, **계획 확정**=완료로 이동 |
| 완료 | 초록 완료 문구, 진행 표시 "계획 완성", 시작 버튼 "공부 계획 완성"(비활성) |

## 기존 기능 (1~6주차)

- **반응형 레이아웃** (4주차): `max-width: 900px` 유동 너비, 768px 이하에서 메뉴·카드·폼을 세로로 배치
- **이메일 신청** (5주차): submit 시 빈칸·형식 오류·완료를 구분해 문구 색과 버튼 상태(신청 완료·비활성) 변경
- **이벤트와 탭** (6주차)

| 이벤트 | 위치 | 함께 바뀌는 것 |
| --- | --- | --- |
| click | 탭 버튼 3개 | 선택 탭 스타일(`is-active`) · `aria-selected` · 보이는 내용 |
| click | 알림 켜기/끄기 버튼 | 버튼 글자 · 버튼 색 · 안내 문구 |
| input | 공부 시간 막대, 이메일 칸 | 안내 문구 · 막대 길이/색 · 입력칸 테두리 |
| change | 할 일 체크박스, 알림 시간 선택 | 완료 개수 문구 · 취소선 · 버튼 활성화 |
