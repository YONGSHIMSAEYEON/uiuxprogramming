# 공부메이트

> 계획부터 복습까지, 매일 공부를 함께 챙겨 주는 스터디 플래너

- 배포 주소: https://yongshimsaeyeon.github.io/uiuxprogramming/
- 저장소: https://github.com/YONGSHIMSAEYEON/uiuxprogramming

## 프로젝트 소개

| 항목 | 내용 |
| --- | --- |
| 서비스 | 공부메이트 — 과목과 목표를 등록하면 하루 공부 계획을 나눠 주는 스터디 플래너 |
| 주요 사용자 | 공부 계획을 세워도 며칠 만에 흐지부지되는 대학생 |
| 서비스 목적 | 해야 할 공부를 작게 나누고, 매일 얼마나 해냈는지 한눈에 보여 줘서 공부 습관을 끝까지 이어 가게 한다 |
| 핵심 행동 | **첫 공부 계획 만들기** — 과목을 적고, 이번 주 목표와 하루 공부 시간을 골라 계획을 확정한다 |
| 완료 조건 | 확정 팝업에서 '계획 확정'을 눌러 **"공부 계획이 만들어졌어요"** 완료 화면에 도착하고, 다음에 할 행동(오늘의 할 일 체크)을 안내받는다 |

## 파일 구조

```
uiuxprogramming/
├── index.html          구조 (header · nav · main 안의 section들 · footer)
├── script.js           행동 (신청 폼 · 탭 · 이벤트 · 계획 만들기 흐름)
├── README.md
└── assets/
    ├── css/style.css   표현 (색 변수 · 반응형 · 상태 class)
    └── images/service.jpg
```

| 영역 | 내용 |
| --- | --- |
| `#about` 서비스 소개 | 소개 문구와 앱 화면 이미지 |
| `#features` 주요 기능 | 오늘의 할 일 · 진도 그래프 · 공부 알림 카드 3개 |
| `#planner` 미리 써 보기 | 탭 3개로 기능 체험 (체크박스 · 공부 시간 막대 · 알림 설정) |
| `#steps` 이용 방법 | 이용 3단계 + **첫 공부 계획 만들기 흐름 (7주차)** |
| `#subscribe` 무료로 시작하기 | 이메일 신청 폼 (입력 중 형식 안내, 신청 완료 후 버튼 비활성) |

## 사용자 흐름

이용 방법의 첫 단계("과목과 이번 주 목표를 등록합니다")를 실제로 해 보는 흐름입니다. 단계는 4개입니다.

```
[첫 공부 계획 만들기] → 1. 과목 입력 → 2. 목표·시간 선택 → 3. 입력 내용 확인 → (확정 팝업) → 4. 완료
                          ↑               ↑                     │
                          └──── 이전 ─────┴──────── 이전 ────────┘
                                                    완료 → [다시 만들기] → 1단계 (모두 초기화)
```

| 단계 | 화면 | 필수 값 | 다음 행동 버튼 |
| --- | --- | --- | --- |
| 시작 | 이용 방법 아래 `#planStart` | — | 첫 공부 계획 만들기 |
| 1 | 과목 이름 입력 | 과목 이름 (공백만 입력도 빈 값으로 처리) | 공부 목표 고르기 |
| 2 | 공부 목표 · 하루 공부 시간 선택 | 공부 목표 / **시험 대비일 때만** 시험 날짜(오늘 이후) | 이전 · 입력 내용 확인 |
| 3 | 입력한 과목 · 목표 · 시간 확인 | — | 이전 · 계획 만들기 → 확정 팝업 |
| 4 | 완료 문구 + 다음에 할 일 안내 | — | 다시 만들기 |

화면 위쪽의 진행 표시(`#planProgress`, `aria-live`)가 `1 / 3 · 계획 만들기 단계` → `2 / 3` → `3 / 3` → `계획 완성`(초록)으로 바뀝니다.

### 상태 정리

| 상태 | 화면 |
| --- | --- |
| 입력 전 | 흐름 영역 숨김, 시작 버튼 "첫 공부 계획 만들기" |
| 입력 중 | 현재 단계 하나만 표시, 진행 표시 `n / 3` |
| 오류 | 고칠 칸에 빨간 테두리(`has-error`, `aria-invalid`) + 칸 아래 수정 방법 문구, 해당 칸으로 커서 이동, 현재 단계에 머무름 |
| 선택 | 시험 대비를 고르면 시험 날짜 칸이 나타나고, 다른 목표로 바꾸면 날짜 칸이 숨겨지며 값도 지워짐 |
| 확인 | 3단계에 입력·선택 값 표시 |
| 확정 팝업 | `<dialog>`로 요약 표시. **다시 확인**=팝업만 닫고 값 유지, **계획 확정**=완료로 이동 |
| 완료 | 초록 완료 문구, 진행 표시 "계획 완성", 시작 버튼 "공부 계획 완성"(비활성) |
| 다시 시작 | 입력 값 · 선택 값 · 오류 · 완료 문구 · 진행 상태 · 시작 버튼을 처음 상태로 되돌리고 1단계로 |

## 인터랙션 시나리오

행동 → 이벤트 → 조건 → 화면 반응 → 다음 상태

| # | 행동 | 이벤트 | 조건 | 화면 반응 | 다음 상태 |
| --- | --- | --- | --- | --- | --- |
| 1 | '첫 공부 계획 만들기'를 누른다 | click | — | 흐름 영역이 열리고 과목 칸에 커서 | 1단계 |
| 2 | 과목 없이 '공부 목표 고르기'를 누른다 | click | `subjectName.value.trim()`이 비었는가? | "공부할 과목 이름을 입력해 주세요. 예) 데이터베이스" + 빨간 테두리 | 1단계 유지 |
| 3 | 과목을 입력한다 | input | 입력값이 생겼는가? | 오류 문구와 빨간 테두리가 사라짐 | 1단계 |
| 4 | 과목을 적고 '공부 목표 고르기'를 누른다 | click | 과목이 있는가? | 2단계 표시, 목표 선택칸에 커서 | 2단계 |
| 5 | 목표 없이 '입력 내용 확인'을 누른다 | click | `planGoal.value`가 비었는가? | "이번 주 공부 목표를 하나 골라 주세요." | 2단계 유지 |
| 6 | 목표로 '시험 대비'를 고른다 | change | 값이 `exam`인가? | 시험 날짜 칸이 나타남 | 2단계 |
| 7 | 날짜 없이 / 지난 날짜로 '입력 내용 확인' | click | 날짜가 비었는가? 오늘 이전인가? | "시험 날짜를 선택해 주세요." / "이미 지난 날짜예요…" | 2단계 유지 |
| 8 | 목표를 다른 것으로 바꾼다 | change | `exam`이 아닌가? | 시험 날짜 칸 숨김 + 값·오류 지움 (검사에서도 제외) | 2단계 |
| 9 | 올바르게 고르고 '입력 내용 확인' | click | 필수 값이 모두 있는가? | 과목 · 목표 · 시간이 확인 화면에 표시 | 3단계 |
| 10 | 3단계에서 '이전'을 누른다 | click | — | 2단계로 돌아가며 고른 값이 그대로 남아 있음 | 2단계 |
| 11 | 값을 고친 뒤 다시 확인 | click | 필수 값이 모두 있는가? | 고친 값이 확인 화면에 다시 반영 | 3단계 |
| 12 | '계획 만들기'를 누른다 | click | — | 확정 팝업에 요약 표시 | 팝업 |
| 13 | 팝업에서 '다시 확인' | click | — | 팝업만 닫힘, 확인 화면 값 유지 | 3단계 |
| 14 | 팝업에서 '계획 확정' | click | — | "○○ · ○○ 계획이 완성되었습니다…" 초록 문구, 진행 "계획 완성", 시작 버튼 비활성 | 완료 |
| 15 | '다시 만들기'를 누른다 | click | — | 모든 값 · 오류 · 진행 상태 초기화, 과목 칸에 커서 | 1단계 |

## 기존 기능 (1~6주차)

- **반응형 레이아웃** (4주차): `max-width: 900px` 유동 너비, 768px 이하에서 메뉴·카드·폼을 세로로 배치
- **이메일 신청** (5주차): submit 시 빈칸·형식 오류·완료를 구분해 문구 색과 버튼 상태(신청 완료·비활성) 변경
- **이벤트와 탭** (6주차)

| 이벤트 | 위치 | 함께 바뀌는 것 |
| --- | --- | --- |
| click | 탭 버튼 3개 | 선택 탭 스타일(`is-active`) · `aria-selected` · 보이는 내용 |
| click | 알림 켜기/끄기 버튼 | 버튼 글자 · 버튼 색 · 안내 문구 |
| input | 공부 시간 막대, 이메일 칸 | 안내 문구 · 막대 길이/색 · 입력칸 테두리 |
| change | 할 일 체크박스, 알림 시간 선택 | 완료 개수 문구 · 취소선 · 버튼 활성화 |

| 8 | 완료 표시: 초록 완료 문구 · "계획 완성" · 시작 버튼 비활성 | 통과 |
| 9 | 다시 시작: 입력 · 선택 · 오류 · 완료 문구 · 진행 상태 · 시작 버튼이 초기화되는가 | 통과 |
| 10 | 기존 기능: 6주차 탭 · 이벤트, 5주차 이메일 신청이 그대로 동작하는가 | 통과 |
| 11 | 모바일: 입력칸 · 버튼 · 오류 문구 · 팝업이 잘리거나 겹치지 않는가 | 통과 |

```
정상     데이터베이스 / 시험 대비(2030-12-10) / 2시간 → 확인 화면 표시
빈 과목  "   " → "공부할 과목 이름을 입력해 주세요. 예) 데이터베이스"  (1단계 유지)
빈 목표  → "이번 주 공부 목표를 하나 골라 주세요."                     (2단계 유지)
빈 날짜  → "시험 대비를 골랐다면 시험 날짜를 선택해 주세요."          (2단계 유지)
지난 날짜 2020-01-01 → "이미 지난 날짜예요. 오늘 이후의 시험 날짜를 골라 주세요."
수정     자료구조 / 매일 복습 / 2시간 → 확인 화면에 그대로 반영, 시험 날짜 칸 숨김·값 삭제
완료     "자료구조 · 매일 복습 계획이 완성되었습니다. 매일 2시간씩 오늘의 할 일로 나눠 드릴게요."
다시 만들기 → 빈 과목 · 목표 미선택 · 하루 1시간 · 오류 없음 · "1 / 3" · 시작 버튼 활성

1100px -> viewport 1085 / content 1085  (가로 스크롤 없음, 세로 스크롤바 15px 제외)
 768px -> viewport  753 / content  753  (가로 스크롤 없음)
 390px -> viewport  375 / content  375  (가로 스크롤 없음, 확정 팝업 16px~359px 화면 안)
```

모바일(768px 이하)에서는 입력칸과 버튼이 가로를 꽉 채우고, 다음 행동 버튼이 위·이전 버튼이 아래에 놓이며, 확인 화면의 항목 이름과 값이 위아래로 배치됩니다.

## 주차별 작업

- 1주차: 첫 웹페이지 만들기, GitHub Pages 배포
- 2주차: HTML로 서비스 소개 페이지 구조 만들기
- 3주차: 외부 CSS로 꾸미기
- 4주차: 반응형 CSS (768px 이하 배치 전환)
- 5주차: JavaScript 이메일 신청 기능
- 6주차: click · input · change 이벤트와 탭 3개
- 7주차: 사용자 흐름 "첫 공부 계획 만들기" (입력 → 선택 → 확인 → 완료, 오류 · 이전 · 다시 시작)
