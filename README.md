# 공부메이트

> 계획부터 복습까지, 매일 공부를 함께 챙겨 주는 스터디 플래너

- 배포 주소: https://yongshimsaeyeon.github.io/uiuxprogramming/
- 저장소: https://github.com/YONGSHIMSAEYEON/uiuxprogramming

## 프로젝트 소개

| 항목 | 내용 |
| --- | --- |
| 서비스 | 공부메이트 — 과목과 목표를 등록하면 하루 공부 계획을 나눠 주는 스터디 플래너 |
| 주요 사용자 | 공부 계획을 세워도 며칠 만에 흐지부지되는 대학생 |
| 서비스 목적 | 해야 할 공부를 작게 나누고, 매일 얼마나 해냈는지 한눈에 보여 줘서 공부 습관을 끝까지 이어 가게 한다 |
| 핵심 행동 | **첫 공부 계획 만들기** — 과목을 적고, 이번 주 목표 · 하루 공부 시간 · 알림을 골라 계획을 저장한다 |
| 완료 조건 | '계획 만들기'(submit)로 저장에 성공해 **"공부 계획이 만들어졌어요"** 완료 화면에 도착하고, 계획이 '내 공부 계획' 목록에 들어간다 |

## 9주차에 추가 · 수정한 것 — 계획 만들기 입력 폼

7주차에 만든 **첫 공부 계획 만들기**(3단계 입력)를 하나의 `<form id="planForm" novalidate>`로 묶고, 사용자가 무엇을 입력해야 하는지 알고 · 잘못 입력하면 고칠 방법을 보고 · 제출 결과를 확인할 수 있게 고쳤습니다. 새 화면을 만들지 않고 기존 `index.html` · `style.css` · `script.js`를 이어서 수정했습니다.

| 구분 | 바꾼 내용 |
| --- | --- |
| 폼 구조 | 1~3단계를 `form` 하나에 넣음. 단계 이동은 `type="button"`, 최종 저장만 `type="submit"`. 모든 칸에 `label for`/`id` 연결, `name` 지정, 도움말 · 오류 문구를 `aria-describedby`로 연결, 필수 칸에 "필수" 표시 |
| 입력 항목 | **텍스트** 과목 이름 · **라디오** 공부 목표(시험 대비 / 과제 제출 / 매일 복습) · **날짜** 시험 날짜 · **선택(select)** 하루 공부 시간 · **체크박스** 매일 공부 알림 받기 · **선택** 알림 시간 |
| 조건부 입력 | ① 목표에서 '시험 대비'를 고르면 시험 날짜 영역이 나타남 ② '매일 공부 알림 받기'를 체크하면 알림 시간 영역이 나타남. 숨길 때는 `hidden` + `disabled` + `aria-expanded="false"`를 함께 적용 → 제출값(`FormData`)에서 빠지고 검사도 하지 않음. 다시 보이면 `disabled`가 풀리고 전에 고른 값이 그대로 남아 있음 |
| 입력 중 피드백 | 과목 칸 아래에 **글자 수(`0 / 20자`)** 와 **조건 충족 여부**(“조금만 더! 2자 이상이어야 해요.” → 초록 “입력 조건을 충족했어요.”)를 `input` 이벤트로 실시간 표시 |
| 오류 표시 · 해제 | 조건을 못 지키면 빨간 테두리 + `aria-invalid="true"` + 칸 아래에 **문제와 고칠 방법** 문구. 고치면 바로 다시 검사해 오류가 사라짐 (오류 문구는 입력할 때마다 새로 띄우지 않고, 이미 오류가 난 칸만 다시 검사) |
| 제출 | `submit` 이벤트 한 곳에서 모든 단계를 다시 검사 → 오류가 있으면 **그 단계를 열고 첫 오류 칸으로 커서 이동**하고 제출을 막음 |
| 제출 중 | 버튼 "저장 중…" + `disabled`, 이전 버튼도 잠금, `form`에 `aria-busy="true"`, `role="status"` 문구 "계획을 저장하고 있어요…" → 여러 번 눌러도 한 번만 저장 |
| 성공 · 실패 | 성공 → 완료 화면 + '내 공부 계획' 목록에 추가(`localStorage`). 실패 → 3단계에 머물며 **입력값 유지**, 빨간 실패 이유 + 버튼이 "다시 시도"로 다시 켜짐 |
| 다시 작성 | 완료 화면의 '새 계획 다시 작성' → 입력값 · 선택 · 추가 영역 · 오류 문구 · 글자 수 · 상태 문구 · 버튼 글자/잠금 · 진행 표시를 모두 처음으로 |
| 정리 | 8주차의 별도 '내 계획 목록에 저장' 버튼과 7주차 확정 팝업은 없앰 → 3단계 확인 화면의 '계획 만들기'(submit) 한 번으로 저장. 중복 과목 검사는 저장 버튼이 아니라 1단계 입력 검사로 옮겨서 입력하는 순간 알 수 있게 함 |

### 입력 조건

| 항목 | 필수 | 조건 | 오류 문구 (문제 + 고칠 방법) |
| --- | --- | --- | --- |
| 과목 이름 | O | 앞뒤 공백을 뺀 2~20자 (`maxlength="20"`) | 빈 값: "과목 이름을 입력해 주세요. 예) 데이터베이스" / 1자: "과목 이름을 2자 이상 입력해 주세요. 지금 1자예요." |
| 과목 이름 | O | 이미 '내 공부 계획'에 있는 과목이 아님 (대소문자 무시) | "'데이터베이스'은(는) 이미 내 공부 계획에 있어요. 다른 과목을 적거나, 목록에서 예전 계획을 지운 뒤 다시 시도해 주세요." |
| 공부 목표 | O | 셋 중 하나 선택 | "이번 주 공부 목표를 하나 골라 주세요." |
| 시험 날짜 | 시험 대비일 때만 | 비어 있지 않고 오늘 이후 | "시험 대비를 골랐다면 시험 날짜를 선택해 주세요." / "이미 지난 날짜예요. 오늘(2026-10-27) 이후의 날짜를 골라 주세요." |
| 하루 공부 시간 | — | 기본 1시간 | — |
| 알림 시간 | 알림 체크 시만 | 시간 하나 선택 | "알림 받을 시간을 골라 주세요. 알림이 필요 없다면 '매일 공부 알림 받기' 체크를 해제해 주세요." |

### 실패 처리 (조건과 코드 위치)

서버 없이 브라우저 저장소(`localStorage`)에 저장하고, 저장에 걸리는 시간은 `setTimeout` 1.2초로 흉내 냈습니다. 아래 세 경우에 실패로 처리합니다.

| 실패 조건 | 안내 | 코드 위치 |
| --- | --- | --- |
| 목록이 최대 5개로 가득 참 | "목록은 최대 5개까지라 저장하지 못했어요. 아래 '내 공부 계획'에서 다 끝난 계획을 지운 뒤 '다시 시도'를 눌러 주세요." | `script.js` `savePlan()` — `savedPlans.length >= maxPlans` (617행) |
| 브라우저 저장소를 쓸 수 없음 (사생활 보호 모드 · 용량 초과 등) | "브라우저 저장소에 저장하지 못했어요. 입력한 내용은 그대로 있어요…" | `storePlans()`가 `false`를 돌려주면 방금 넣은 계획을 빼고 실패 처리 (634행, `storePlans()` 716행) |
| 확인용 실패 스위치 체크 | "저장하지 못했어요. (확인용 실패) 입력한 내용은 그대로 있어요. 체크를 해제하고 '다시 시도'를 눌러 주세요." | 3단계의 '확인용: 이번 저장을 실패로 만들기' 체크박스(`index.html` 210행, `name`이 없어 제출값에 안 들어감) → `savePlan()` 612행 |

세 경우 모두 `setSubmitState("error", 문구)`(555행)로 버튼을 "다시 시도"로 다시 켜고, 입력칸은 건드리지 않아 값이 그대로 남습니다.

### 확인 순서

브라우저에서 '이용 방법 > 첫 공부 계획 만들기'를 누른 뒤 아래 순서대로 확인합니다.

1. **빈 값 제출** — 과목을 비운 채 '공부 목표 고르기' → 빨간 오류 "과목 이름을 입력해 주세요…", 커서가 과목 칸으로
2. **잘못된 값** — `D` 한 글자 입력 → 글자 수 `1 / 20자`, "조금만 더! 2자 이상이어야 해요.", 오류 문구가 "2자 이상… 지금 1자예요."로 바뀜
3. **오류 수정** — `데이터베이스`로 고침 → `6 / 20자`, 초록 "입력 조건을 충족했어요.", 빨간 테두리 · 오류 문구 사라짐
4. **선택 없이 다음** — 2단계에서 목표를 고르지 않고 '입력 내용 확인' → "이번 주 공부 목표를 하나 골라 주세요."
5. **조건부 영역** — '시험 대비' 선택 → 시험 날짜 영역 표시(입력 가능) / '매일 공부 알림 받기' 체크 → 알림 시간 영역 표시. 비운 채 '입력 내용 확인' → 두 칸 모두 오류, 커서는 시험 날짜로
6. **조건부 오류 수정** — 2020-01-01 → "이미 지난 날짜예요…", 2030-12-10으로 고치면 해제 / 알림 체크 해제 → 영역 숨김 · `disabled` · 오류 해제
7. **조건부 영역 숨김** — 목표를 '매일 복습'으로 바꿈 → 시험 날짜 영역 숨김 · `disabled` (값은 남아 있지만 제출값에서 빠짐)
8. **확인 화면** — 과목 · 목표 · 하루 공부 시간 · 공부 알림이 표시됨
9. **실패** — '확인용: 이번 저장을 실패로 만들기' 체크 후 '계획 만들기' → 1.2초 동안 "저장 중…"(버튼 잠금) → 빨간 실패 안내, 버튼 "다시 시도", 입력값 그대로
10. **다시 시도 성공** — 체크 해제 후 '다시 시도' → 완료 화면, 목록에 카드 추가
11. **다시 작성** — '새 계획 다시 작성' → 빈 과목 · `0 / 20자` · 목표 미선택 · 추가 영역 숨김 · 버튼 "계획 만들기" · 상태 문구 없음
12. **중복 과목** — 다시 `데이터베이스` 입력 → "이미 저장한 과목이에요." 표시, 다음을 누르면 중복 오류
13. **가득 참 실패** — 계획 5개 저장 후 6번째 저장 → 실패 안내 → 목록에서 하나 지우고 '다시 시도' → 성공

## 파일 구조

```
uiuxprogramming/
├── index.html          구조 (header · nav · main 안의 section들 · footer)
├── script.js           행동 (신청 폼 · 탭 · 이벤트 · 계획 만들기 폼 · 계획 목록)
├── README.md
└── assets/
    ├── css/style.css   표현 (색 변수 · 반응형 · 상태 class)
    └── images/service.jpg
```

| 영역 | 내용 |
| --- | --- |
| `#about` 서비스 소개 | 소개 문구와 앱 화면 이미지 |
| `#features` 주요 기능 | 오늘의 할 일 · 진도 그래프 · 공부 알림 카드 3개 |
| `#planner` 미리 써 보기 | 탭 3개로 기능 체험 (체크박스 · 공부 시간 막대 · 알림 설정) |
| `#steps` 이용 방법 | 이용 3단계 + **첫 공부 계획 만들기 폼 `#planForm` (7·9주차)** + **내 공부 계획 목록 `#planList` (8주차)** |
| `#subscribe` 무료로 시작하기 | 이메일 신청 폼 (입력 중 형식 안내, 신청 완료 후 버튼 비활성) |

## 사용자 흐름

```
[첫 공부 계획 만들기] → 1. 과목 → 2. 목표 · 시간 · 알림 → 3. 확인 → (submit: 저장 중) → 4. 완료
                         ↑              ↑                    │            │
                         └──── 이전 ────┴─────── 이전 ───────┘      실패 → 3단계 유지, 다시 시도
                                                         완료 → [새 계획 다시 작성] → 1단계 (모두 초기화)
                                                              → [내 공부 계획 보기] → 목록
```

화면 위쪽의 진행 표시(`#planProgress`, `aria-live`)가 `1 / 3` → `2 / 3` → `3 / 3` → `계획 완성`(초록)으로 바뀝니다.

## 내 공부 계획 목록 (8주차 중간고사)

완성한 계획이 **내 공부 계획** 목록에 쌓입니다. 목록은 브라우저 저장소(`localStorage`)에 보관해서 새로고침해도 남습니다.

```
내 공부 계획 목록 ── [목표로 찾기] ── 결과 없음 → [전체 보기] / [새 계획 만들기]
                  ├─ [자세히 보기] ↔ [접기]
                  └─ [삭제] → 확인 팝업 → [취소] / [삭제]
```

| 사용자 행동 | 확인할 조건 | 반응 |
| --- | --- | --- |
| '목표로 찾기'에서 목표 고르기 (change) | 고른 목표의 계획이 있는가? | 있으면 그 카드만, 없으면 "'과제 제출' 목표로 저장한 계획이 없어요…" + [전체 보기] [새 계획 만들기] |
| 카드 '자세히 보기' | 시험 대비인가? 시험일이 지났는가? | 목표 · 하루 공부 시간 · 알림 · 저장한 날, 시험 대비면 "D-52", 지났으면 빨간 안내 |
| 카드 '삭제' → 팝업 '취소' / '삭제' | — | 취소: 그대로 / 삭제: 카드 제거, 결과가 0개면 결과 없음 안내 |
| 결과 없음의 '새 계획 만들기' | — | 계획 만들기 폼을 초기화하고 1단계로 이동 |

## 기존 기능 (1~6주차)

- **반응형 레이아웃** (4주차): `max-width: 900px` 유동 너비, 768px 이하에서 메뉴·카드·폼을 세로로 배치
- **이메일 신청** (5주차): submit 시 빈칸·형식 오류·완료를 구분해 문구 색과 버튼 상태(신청 완료·비활성) 변경
- **이벤트와 탭** (6주차)

| 이벤트 | 위치 | 함께 바뀌는 것 |
| --- | --- | --- |
| click | 탭 버튼 3개 | 선택 탭 스타일(`is-active`) · `aria-selected` · 보이는 내용 |
| click | 알림 켜기/끄기 버튼 | 버튼 글자 · 버튼 색 · 안내 문구 |
| input | 공부 시간 막대, 이메일 칸 | 안내 문구 · 막대 길이/색 · 입력칸 테두리 |
| change | 할 일 체크박스, 알림 시간 선택 | 완료 개수 문구 · 취소선 · 버튼 활성화 |

## 주차별 작업

- 1주차: 첫 웹페이지 만들기, GitHub Pages 배포
- 2주차: HTML로 서비스 소개 페이지 구조 만들기
- 3주차: 외부 CSS로 꾸미기
- 4주차: 반응형 CSS (768px 이하 배치 전환)
- 5주차: JavaScript 이메일 신청 기능
- 6주차: click · input · change 이벤트와 탭 3개
- 7주차: 사용자 흐름 "첫 공부 계획 만들기" (입력 → 선택 → 확인 → 완료, 오류 · 이전 · 다시 시작)
- 8주차(중간고사): 완성한 계획을 "내 공부 계획" 목록에 저장 (중복·최대 개수 검사, 목표로 찾기·결과 없음 안내, 자세히 보기, 삭제 확인·취소)
- 9주차: 계획 만들기를 하나의 입력 폼으로 개선 (label · 도움말 연결, 글자 수 · 조건 실시간 표시, 오류 표시 · 해제, 선택에 따른 추가 입력과 `disabled`, submit 최종 검사, 저장 중 중복 방지, 성공 · 실패 · 다시 시도, 다시 작성 초기화)
